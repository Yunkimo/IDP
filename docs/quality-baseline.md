# 提醒质量口径（B2 待评审提案）

原 #6 同时写“30 秒扫描”“创建到期时间 now+60 秒”“60 秒内收到”，计时起点有歧义。
本文件保留原问题，以下口径随 PR 提交 A/C 评审，不声称三方已确认或覆盖教师原始要求。

| 项目 | 当前测量或目标 | 验证状态 |
|---|---|---|
| 基本正确性 | 不能早于计划到期触发；正确通知并写回状态 | 固定时钟与真实网络测试 |
| 计时起点 | 计划 remind_at 对应的 UTC 时刻 | 脚本明确记录 |
| B2 观测终点 | WebSocket 客户端收到事件时刻 | 当前实测 |
| 三端验收终点 | 桌宠/小程序界面实际展示时刻 | 待联调，不用收包替代 |
| 联调候选配置 | 扫描间隔 ≤2 秒，目标到期至展示 ≤5 秒 | 本次仅验证 1 秒扫描到收包；GUI 未验 |
| 默认配置 | 30 秒扫描，分别报告实际延迟 | 不套用 ≤5 秒结论 |
| 样本 | 每种配置至少 30 次，报告全部失败/超时/重复 | 原始 JSON 随报告提交 |
| 分布 | 成功率、p50/p95/max，nearest-rank 分位数 | 按成功收包样本计算，另列失败分母 |
| 时间误差 | 当前服务与客户端同机；报告墙钟/单调钟增量差 | 无跨机器误差结论 |

默认组脚本用 35 秒作为本次观测失败阈值，不代表团队已承诺该 SLA。
改动阈值必须说明理由与前后数据；不得以无限等待“最终收到”代替限时验证。
