# 演示脚本（C 端组织）

> 视频由团队成员本人录制；本脚本提供镜头顺序、操作步骤、预期结果与前置说明。
> 录制时遮挡 API Key、openid、手机号等隐私信息；记录版本 SHA 与章节时间点。

## 前置准备

- 部署 SHA：记录 `git rev-parse HEAD`（当前演示版本）
- 环境：后端运行（`scripts/run-backend.ps1`）；小程序开发者工具 + 真机同 WiFi
- 依赖外部服务的能力：图片识别需视觉模型额度（硅基流动）；订阅提醒需微信模板与 B3 后端；离线推送需公网 HTTPS（C4 路线 2/3）
- 演示前清理数据：`scripts/reset_demo.py --yes`（演示库）

## 章节与步骤

| # | 章节 | 操作 | 预期画面 | 前置 |
|---|---|---|---|---|
| 1 | 启动与健康检查 | 启动后端，浏览器开 `/api/health` | `{"status":"ok"}` | 无 |
| 2 | 手机查课表 | 小程序「今日/课表」页浏览 | 按第 X 周过滤的课表 | 无 |
| 3 | 图片识别导入 | 课表页「识」→ 拍课表照片 → 确认弹窗 → 导入 | 课程列表出现，教师/周次正确 | 视觉模型 |
| 4 | 桌面同步 | 桌宠说「加一个明天上午的日程」；手机切「日程」页 | 桌宠创建后手机即时刷新出现 | 桌宠端 + WS |
| 5 | 实时刷新 | 后端 curl 加课程，手机课表页停留 | 约 1 秒自动出现新课 | WS |
| 6 | 断线恢复 | 杀后端进程 → 手机操作报错 → 重启后端 → 下拉/自动重连 | 数据恢复 | 无 |
| 7 | 订阅提醒 | 日程页带提醒时间的任务点「订阅提醒」→ 微信弹窗点允许 → 到期（联调可把提醒设 1 分钟后）→ 手机收到订阅消息 | 微信收到消息（小程序可关闭） | B3 + 模板 + 真机 |
| 8 | 离线提醒 | 关闭小程序，等待到期 | 微信服务通知送达 | 同上 |
| 9 | 失败恢复 | 断开 WiFi 后操作 → 错误提示；恢复网络后重试 | 提示明确、数据一致 | 无 |
| 10 | 收尾 | 展示 CI 页面与测试报告链接 | CI 全绿 | 网络 |
